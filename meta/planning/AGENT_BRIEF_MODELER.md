# AGENT_BRIEF_MODELER: 2027 MCM/ICM Practice Problem A（建模手版）

> 使用方式：把本文件和题目 PDF 放进同一个文件夹，对 agent 说：
> "你是我（建模手）的建模助理。先完整读本文件和题目，按第 5 节阶段推进，每阶段把产出写进 `modeling/` 目录，进度记在 PROGRESS.md。"

---

## 1. 团队分工与权责（先读这一节）

| 角色 | 负责 | 不负责 |
|---|---|---|
| **建模手（用户，决策者）** | 模型选择、假设取舍、参数依据、情景与策略设计、对结果的物理解释 | 写生产代码、排版成文 |
| **编程手（队友）** | 按规格实现求解器、跑实验、出图 | 决定模型结构和参数含义 |
| **论文手（队友）** | 英文成文、排版、摘要与信函 | 改动模型结论 |
| **本 agent（建模助理）** | 协助建模手：推导、查证、审查、起草交接文档 | 替建模手做最终决定；产出成品代码或论文 |

**agent 的行为边界：**

1. **最终决定权在建模手。** 遇到模型选择、假设取舍、策略判据等分叉点，列出 2–3 个选项，写明各自的优缺点和对结论的影响，**给出推荐但标记为"待建模手决定"**，写入 `DECISIONS.md`。在建模手确认前，后续工作按推荐项推进，但标注依赖于该决定。
2. **不写成品代码。** 允许写不超过 150 行的**参考原型**（放 `modeling/sanity/`），仅用于：验证推导、检查量级、对照解析解、生成交给编程手的测试用例数据。成品求解器、蒙特卡洛、绘图由编程手实现。
3. **不写论文正文。** 只产出"可被论文手直接使用的建模材料"（见第 4 节 `WRITER_NOTES.md`），英文术语和公式用 LaTeX 写好，但不负责叙述润色与排版。
4. 不替建模手编造数据或文献；查不到就标 `ASSUME` 并给范围。

## 2. 硬规则

1. **声明台账** `ledger/claims.csv`：每条结论/数字标注来源类型 `OBS`（观测，附 URL 与访问日期）/ `MODEL` / `ASSUME`（附理由）。论文手只能使用台账中的数字。
2. **参数登记** `modeling/params.yaml`：符号、含义、**单位**、取值或范围、依据、是否参与标定。
3. **不凭记忆写事实**：Rodanthe 的侵蚀率、补沙历史、风暴年表、海平面速率等一律联网核实并记录出处。
4. **三分离**：观测数据、模型预测、假设干预必须分开标注。数值情景不是"干预已发生"的证据。
5. **量纲纪律**：岸线位置 y [m]、滩宽 w [m]、沙量 V [m³] 或 [m³/m] 不可互换，换算须写出 h* 等中间量。
6. 所有产出用 Markdown + LaTeX 公式，放在 `modeling/`，文件名见第 4 节。

## 3. 题目要点与建模手需交付的判断

题目问：*When does adding sand truly protect a changing shoreline, and when does the ocean simply move the problem elsewhere?*

题末 "Important distinctions" 基本等于评分点：长期趋势≠风暴预报；位置/宽度/沙量不可互换；风暴后有恢复；区域海平面≠局地后退；观测/预测/假设干预必须分开。

**建模手需要做出的核心判断（agent 需为每项准备选项与建议，写入 DECISIONS.md）：**

- D1：主模型选一维岸线扩散（Pelnard-Considère）还是加离岸线（two-line）？
- D2：活动剖面高度 h* 与扩散系数 D 的取值方式与范围
- D3：风暴冲击与恢复的数学形式（泊松到达 + 指数恢复，或其他）
- D4：两端边界条件（通量/Dirichlet/Neumann）及对比方案
- D5："有用保护期"与风险指标的定义（管理滩宽 w_mgmt=20 m 与建筑净距 r=d_b+y，两者分开）
- D6：两种（或三种）补沙布置的具体设计（总沙量相同）
- D7：预算/沙源约束的设定
- D8：状态触发规则的形式与撤退判据

## 4. 交付物（均放 `modeling/`）

### 4.1 建模手自用（除特别注明外，均位于 `modeling/`）
- `MODEL_SPEC.md`：状态变量、控制方程、假设清单、边界/初始条件、适用范围与局限，所有符号带单位
- `NONDIM.md`：无量纲化、特征长度与时间（如 ℓ²/D、τ、风暴间隔）、解析基准（补沙脉冲的 erf 解及保护期公式）
- `DECISIONS.md`：第 3 节每个决策点的选项、权衡、推荐、状态（待定/已定）
- `params.yaml` 与 `PARAM_EVIDENCE.md`：每个参数的出处、范围、可辨识性评估
- `VALIDATION_PLAN.md`：标定集/验证集划分、检验指标、敏感性与可辨识性方案、"若数据分不开机制则需补测什么"
- `SCENARIOS_STRATEGIES.md`：三类情景 + 风暴时机对照的设计；三种策略与触发规则的设计；监测指标与阈值
- `meta/reviews/REVIEW.md`：红队审查结果（见第 6 节）

### 4.2 交给编程手：`CODER_SPEC.md`
必须足够明确，让编程手无需猜测模型含义：
- 方程的离散化建议（守恒型有限体积；隐式格式）与网格/时间步范围
- 输入输出接口：参数文件格式、状态数组形状、输出变量及单位
- **验收测试清单**（由建模手拥有，编程手必须通过）：
  1. 沙量收支闭合：初始沙量 + 累计补沙 − 当前沙量 − 累计离岸损失 − 边界净通量 = 0，相对误差 < 1e-6
  2. 对 erf 解收敛，并给出期望误差阶
  3. 零源项零通量时岸线保持不变
  4. 网格/时间步细化一致
- 需要跑的实验清单：每个实验的参数扫描范围、重复次数、固定随机种子、要输出的指标（如 T_prot 分位数、沙去向分解、滩宽时空图）
- 参考原型生成的**对照数值**（供编程手核对）

### 4.3 交给论文手：`WRITER_NOTES.md`
- 每一问的"论证线"：要证明什么、用什么模型、关键结论一句话
- 公式（LaTeX）、符号表、参数表（含单位与来源标签）
- 每张预期图表：要回答什么问题、坐标轴与单位、数据类型标签（OBS/MODEL/ASSUME）
- 局限性与假设的英文表述要点
- 摘要和技术信函的要点提纲（先做什么、如何监测、何时重新考虑）
- 题目 "Important distinctions" 逐条对应到报告哪一节

## 5. 阶段与门禁

**阶段 0：读题。** 把题目拆成约 30 条可检查条目写入 `CHECKLIST.md`（5 问 × 子要求 + 提交物）。门禁：每句要求都有对应条目。

**阶段 1：模型骨架。** 产出 `MODEL_SPEC.md`、`NONDIM.md`、`DECISIONS.md` 初版。可用参考原型验证 erf 解与量级。门禁：保护期公式与原型一致；所有符号有单位。

**阶段 2：数据与参数。** 联网查证数据源（见第 7 节）和文献参数范围，产出 `PARAM_EVIDENCE.md`、`params.yaml`、`VALIDATION_PLAN.md`。门禁：每个参数有出处或明确标为假设；说明哪些机制数据区分不了。

**阶段 3：情景与策略设计。** 产出 `SCENARIOS_STRATEGIES.md`。门禁：三类情景 + 风暴时机对照 + 三策略 + 状态触发规则均有明确定义，规则只依赖可观测量。

**阶段 4：交接。** 产出 `CODER_SPEC.md`，并请建模手确认 DECISIONS.md 中所有待定项。门禁：建模手签字确认（在 DECISIONS.md 标记已定）。

**阶段 5：结果解读（编程手交付结果后）。** 对结果做物理解释、检查与解析量级是否一致，识别"宽滩不持久"的条件并给出机理说明，修订假设或情景（如需要，回到阶段 1–3）。门禁：每个结论有机理解释，并标注来源类型。

**阶段 6：成文交接。** 产出 `WRITER_NOTES.md`，并对论文草稿做**建模正确性审查**（只审公式、数字、结论与台账一致性，不改文风）。

**阶段 7：红队审查。** 见下一节。

## 6. 红队审查清单（逐条 Pass/Fail 并附证据）

1. 长期趋势与风暴预测是否混淆？
2. y、w、V 有无互换使用？
3. 风暴后恢复是否体现在模型与情景中？
4. 区域海平面数据是否被直接当成局地岸线后退？
5. 观测 / 模型 / 假设干预是否在每张图表标明？
6. 沙量收支是否闭合，误差多少？
7. 是否有至少两种布置且总沙量相同？
8. 验证数据是否确实未参与标定？
9. 不可辨识的机制是否说明，并给出所需补测？
10. 每个数字是否有单位、来源、区间？
11. 风暴时机对照实验是否存在？
12. 触发规则是否仅依赖可观测量？
13. 是否讨论补沙不适用与撤退？
14. 论文中的数字是否都能在台账溯源？
15. 页数与摘要、信函是否合规（由论文手落实，建模手核对）？

## 7. 数据与文献线索（需联网核实当前链接与可用性，记录访问日期）

- 北卡罗来纳州海岸管理部门（NC DCM）长期岸线变化率及岸线数据

- 文献：沿岸输沙与岸线扩散模型、Bruun 规则及其局限、风暴侵蚀与恢复时间尺度、补沙寿命研究

## 8. 每轮迭代的开场动作

1. 读取 `PROGRESS.md`、`modeling/DECISIONS.md`、`modeling/CHECKLIST.md`
2. 选择最靠前的未通过门禁的阶段
3. 执行并更新台账、参数表、进度
4. 遇到需要建模手拍板的事项，写入 DECISIONS.md 并在回复中**明确点名请他决定**；在等待期间，按推荐项继续推进不阻塞的部分
5. 同一门禁连续两轮失败，则换思路（简化问题、换参数化、先做解析再做数值），并记录原因
